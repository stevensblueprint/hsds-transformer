# Blueprint knowledge

1. Find the existing glossary, decision record, onboarding note, or repository guide. Check nearby guidance before adding a new document.
2. Separate observed behavior, a human decision, and an unresolved hypothesis. Cite the source path and revision or the supplied decision record; include why the fact matters and the condition that could make it stale.
3. Write the smallest useful update in the authorized destination. Keep domain terms in the glossary and implementation rationale beside the relevant decision or code. Consolidate an existing explanation rather than adding a competing one.
4. Show the changed text and source. If evidence conflicts or the decision was never made, record the open question instead of inventing agreement.

Blueprint PRDs and review comments remain human-written. Assist with factual notes and questions; preserve the author's wording and decision ownership. Use only material authorized for this project; exclude secrets and unrelated workplace context.
